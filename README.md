## 第一周工作周报

**汇报人**：Steven Huo ｜ **周期**：2026-09-07 至 2026-09-12 ｜ **岗位**：AI 产品经理实习生

### 一、本周概览

本周核心目标是熟悉 AI 产品经理的工作流，建立行业认知与技术规范认知。截至周五，模块一（toB 平台产品）三个任务全部完成并入库待审，共产出 3 份正式文档、沉淀 2 份可复用的工作规范提示词，仓库累计 7 次 commit。模块二（模型能力边界）因依赖项未就绪主动滞后，模块三（商业化指标）排入下周。

### 二、重点工作

**1. 模块一交付：toB 平台产品的竞品调研与转型分析 🟢**

完成竞品底座对照（蝉镜、CapCut for Business、HeyGen 三家 × 11 项底座能力，每格附证据出处）与剪映 toB 转型分析全文（约 8800 字，含 18+ 条可追溯可验证的信息源清单）。
过程中有一处关键修正：分析初稿假设剪映没有 toB 形态，重新取证后发现剪映团队版已存在三年且仍在更新服务协议，据此把命题从"从 0 到 1 建企业版"修正为"团队版为什么长不成内容生产平台"。

**2. 建立 AI 协同办公的工作规范 🟢**

本周全部产出以"本人做判断与取舍、AI 助理做检索与沉淀、逐模块审批入库"的方式完成。为解决 AI 产出的可信度问题，沉淀了两份可复用规范：信息源质量审计提示词（功能判定必须持官网证据、证据分时效等级、查不到标未披露并记录检索范围）和产品文档文风规范（结论先行、自然段叙事、禁用口播体表达）。这两份规范在任务 3 的重写中实际跑通过一轮，证明可用。

**3. 任务优先级取舍 🟢**

模块二因 API key 未注册且技术向较重，判断滞后完成不影响第一周核心目标，先行搁置；SQL 练习判断当前 AI 编程环境下"手撕 SQL 取数"不是 AI 产品经理岗位的硬性要求，选择跳过、之后补习。原则是先保证主线交付，再用交付后的缓冲期集中迭代完善。

### 四、问题与反思

**AI 提效的另一面是验证成本。** AI 助理做调研和写作确实快，但快是有代价的：一是它跳过了我本该自己走的思考环节，二是它给出的信息需要逐条验证是否如实、可追溯。任务 3 初稿里"剪映没有企业形态"就是一个基于过时印象的错误假设，如果不重新取证，这个错误会直接进交付物。我据此立了一条工作纪律：写进文档的功能判定必须有官网或官方文档证据，查不到就标"未披露"并写明查了哪些地方。这条纪律已经固化成提示词，后续每个调研类任务复用。

**新领域的信息源筛选是绕不开的手工活。** 本周踩过两个典型的坑：腾讯智影官网还在正常展示，但业务实际已于 2025 年中停服退款，只看官网会误判竞品状态；剪映团队版的真实价格在官网没有公开页面，只能从渠道商处拿到量级参考。结论是证据要分级使用，时效和权威等级要如实写进文档，不能为了让结论好看而隐去证据的弱点。

**业务理解没法外包给 AI。** AI 能替代检索、结构化和文字工作，但替代不了亲身体验产品和独立下判断。术语卡任务原计划是我口述理解、AI 模拟外行给反馈，实际执行时发现大部分术语我自己就不熟，于是把交付形态改成先建"错题集"式的术语手册，先补输入再练输出。对新人来说，第一周把基础认知补齐，比在形式上完成"试讲"更重要。

**先交付，再迭代。** 本周时间boxed 很紧，取舍是主动做的：滞后模块二、跳过 SQL、把深入讨论留到交付后。宁可先交 60 分的东西快速迭代，也不在单一任务上恋战，这是我作为实习生对"按时交付是职场底线"这一原则的践行方式。
